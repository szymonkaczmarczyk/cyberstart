Architektura i routing

Cyberstart to statyczna aplikacja: HTML, CSS i moduły ES, bez frameworka i bez kroku budowania. Nie ma backendu, kont ani analityki. Wszystko, co robi użytkownik, zostaje w jego przeglądarce. 

index.html ──► js/app.js      router, mapa, widok gry, wynik
                 │
                 ├──► js/games/index.js   rejestr gier (kolejność = ścieżka)
                 │       └──► js/games/<id>.js   jedna gra = jeden moduł
                 │              └──► ui, terminal-engine, config-audit,
                 │                   log-viewer, scenario
                 ├──► js/progress.js      stan w localStorage
                 ├──► js/badges.js        odznaki
                 └──► js/resources.js     „Kolejny krok w praktyce”
sw.js ──► offline: najpierw sieć, potem pamięć podręczna

Routing działa na hashu adresu, więc aplikacja działa na każdym hostingu statycznym bez konfiguracji przekierowań:

AdresWidok
#/Mapa nauki: hero, sekcja „Dziś” (wyzwanie dnia, seria, odznaki), kategorie z grami, lista odznak.
#/gra/{id}Gra: nagłówek, przełącznik poziomu (jeśli gra go ma), „minuta teorii”, pasek postępu, plansza gry.
#mapa, #odznakiPrzewinięcie mapy do sekcji, bez zmiany widoku.
każdy innyWidok 404 w aplikacji. Plik 404.html obsługuje błędne ścieżki po stronie serwera.

Przy zmianie trasy aplikacja przerywa nasłuch klawiatury poprzedniej gry (AbortController) i przenosi fokus na <main> dla czytników ekranu. Przy pierwszym wczytaniu fokus zostaje na początku strony, żeby link „Przejdź do treści” był pierwszy pod klawiszem Tab.

Przykład: najmniejsza gra z quizem

import { runQuiz, draw } from '../ui.js';

const POOL = [{
  prompt: 'Co oznacza otwarty port?',
  options: [
    { label: 'Program na nim nasłuchuje', correct: true, why: 'Każdy otwarty port to drzwi do pilnowania.' },
    { label: 'Kabel jest odłączony', why: 'Port to pojęcie logiczne.' }
  ]
}];

export default {
  id: 'przyklad',
  title: 'Przykładowa gra',
  category: 'sieci',
  icon: 'plug',
  minutes: 5,
  levels: true,
  summary: 'Krótki quiz o portach.',
  lesson: ['Port to numer drzwi, za którymi czeka program.'],
  takeaways: ['Zamykaj porty, których nie potrzebujesz.'],
  async mount(stage, ctx) {
    const questions = draw(POOL, 5, ctx.level);
    const score = await runQuiz(stage, ctx, questions);
    ctx.finish({ score, max: questions.length });
  }
};

Jak dodać grę

KrokCo zrobić
1Utwórz js/games/<id>.js według kontraktu powyżej.
2Dodaj import i wpis w tablicy GAMES w js/games/index.js. Kolejność w tablicy to kolejność na ścieżce nauki.
3Style dopisz do css/games.css, używając tokenów.
4Jeśli mechanika jest nietypowa, dodaj jej obsługę do autoplayera w tests/e2e/helpers.js (funkcja special()) albo oznacz przycisk atrybutem data-autoplay.
5Uruchom npm run test:e2e. Nowa gra zostanie automatycznie przetestowana: przejście, telefon, oba motywy, dostępność.

Obiekt ctx

OBIEKTctx

Drugi argument mount. Łączy grę z resztą aplikacji: paskiem postępu, zapisem wyniku i cyklem życia widoku.

Znaczenie kluczy

KluczOpis
ctx.level'podstawowy' albo 'zaawansowany'. Dla gier bez levels zawsze 'podstawowy'.
ctx.signalAbortSignal przerywany przy opuszczeniu gry. Przekazuj go do onKey, żeby skróty klawiszowe nie działały po zmianie widoku.
ctx.stageTen sam element, który dostaje mount.
ctx.progress(zrobione, wszystkie)Aktualizuje pasek postępu i licznik, np. 3/12.
ctx.hideProgress()Chowa pasek, gdy zdradzałby odpowiedź. Panel audytu pokazuje go dopiero po pierwszym audycie.
ctx.answer(pytanie, poprawnie)Zapisuje odpowiedź na liście błędów do powtórki. runQuiz woła go sam po każdej odpowiedzi, więc gra z quizem nie musi nic robić.
ctx.finish({ score, max })Zapisuje wynik i rysuje ekran wyniku. XP = round(100 × score / max), zapamiętywany jest najlepszy wynik. Przy okazji: seria dni, wyzwanie dnia, nowe odznaki, lista „Zapamiętaj” i „Kolejny krok w praktyce”.

Przykład

mount(stage, ctx) {
  const stop = onKey(ctx.signal, (event) => {
    if (event.key === 'a') decide(true);
  });
  ctx.progress(0, 12);
  ctx.finish({ score: 9, max: 12 });
}

createTerminal

FUNKCJAcreateTerminal(options)js/terminal-engine.js

Symulator terminala Linuksa na wirtualnym systemie plików. Obsługuje potoki |, przekierowania > i >>, wzorce * i ?, cudzysłowy i \ , uzupełnianie Tab i historię strzałkami.

Opcje

OpcjaWymaganaOpis
treetakDrzewo plików zbudowane z dir({...}) i file(treść, tryb, właściciel). Domyślny tryb to -rw-r--r--, domyślny właściciel to użytkownik.
user, hosttakPrompt user@host. Katalog domowy to /home/{user}.
intronieLinie powitalne: tablica [tekst, klasa].
quickniePolecenia do wstawienia jednym dotknięciem (ułatwienie na telefonie).
onRun(state)nieWywoływane po każdym poleceniu. state zawiera cwd, last (nazwa, flagi, argumenty, pattern i matched dla grep), read (odczytane pliki).
extraCommandsnieDodatkowe polecenia gry: { nazwa: (argv, stdin) => linie }. Linia to tekst albo { text, cls }. Rzucony Error wypisuje się na czerwono.

Polecenia wbudowane

PoleceniaOpis
pwd ls cd catPoruszanie się i czytanie. ls -a -l, cat ./-nazwa. Uprawnienia odczytu są sprawdzane.
grep find filegrep -i -v -c, find KATALOG -name -size -type, rozpoznawanie typu po zawartości.
sort uniq wc head tailsort -r -n, uniq -c -u, wc -l, head/tail -n N. Działają na plikach i w potokach.
base64 chmod echo mkdir touch rmbase64 -d, chmod 600 i chmod u+r, zapis przez >. rm działa tylko w katalogu domowym, a rm -rf / jest zablokowane z wyjaśnieniem.
whoami id hostname uname ip date history clear man sudoInformacje i pomoc. sudo wyjaśnia, co by zrobiło, ale niczego nie uruchamia.

Przykład

const terminal = createTerminal({

  user: 'kursant',
  host: 'kali',
  extraCommands: { ps: () => ['USER PID COMMAND', 'root 1 /sbin/init'] },
  onRun: (state) => checkMission(state)
});
stage.append(terminal.element, terminal.quickBar);

examPool i egzamin

EKSPORTexport function examPool()

Opcjonalny eksport gry. Zwraca samodzielne pytania w formacie runQuiz. Egzamin (js/games/egzamin.js) bierze po jednym pytaniu z każdego tematu, uzupełnia losowo do 25 i pomija pytania zaawansowane.

ZasadaOpis
SamodzielnośćPytanie musi być zrozumiałe bez planszy gry. Pytania odwołujące się do konkretnego logu czy nagrania ruchu nie trafiają do puli.
RejestracjaNową pulę dopisz do tablicy TOPICS w egzamin.js: [tytuł, id gry, funkcja].
Próg80%. Po zaliczeniu odznaka „Egzamin zaliczony”. Wynik trafia do zapisu jak każda inna gra.
Do powtórkiTematy z błędnymi odpowiedziami pojawiają się jako linki do gier.
topicQuestions()Eksport z egzamin.js: wszystkie pytania ze wszystkich tematów, także zaawansowane, z dopisanym topic i topicId. Korzysta z niego powtórka błędów.

Powtórka błędów

GRAjs/games/powtorka.js

Gra „Powtórka błędów” wraca do pytań, na które padła zła odpowiedź w quizie albo na egzaminie. Sesja ma 10 pytań: najpierw błędy, a resztę dopełniają losowe pytania z ukończonych gier (na początku nauki z całego kursu). Dobra odpowiedź zdejmuje pytanie z listy, a mapa pokazuje na karcie licznik „N do powtórki”.

Jak działa lista błędów

KrokOpis
1runQuiz woła ctx.answer(pytanie, poprawnie), a ten noteAnswer(idGry, prompt, poprawnie) z progress.js. Na egzaminie i w powtórce zamiast id gry liczy się topicId pytania.
2Klucz to mistakeKey(idGry, prompt), czyli idGry:skrót. Skrót to FNV-1a z treści pytania zapisany w systemie 36, np. porty:10hop35.
3Zła odpowiedź zapisuje klucz z datą, dobra go usuwa. Lista ma limit 300 wpisów, po przekroczeniu odpadają najstarsze.
4Powtórka buduje słownik kluczy z topicQuestions() i bierze pytania, których klucze są na liście. Kluczy bez pasującego pytania (np. pytanie zmieniono) po prostu nie pokazuje.

Decyzje

DecyzjaPowód
Zapisywany jest klucz, nie treśćPytania zawierają autorski HTML. Gdyby treść trafiała do localStorage, zmanipulowany plik importu mógłby wstrzyknąć kod. Klucz pasuje do wzorca i nie da się go wyświetlić jako HTML.
Do powtórki wracają pytania z examPool()Tylko one są samodzielne i zrozumiałe bez planszy gry. Pytania z mechanik bez runQuiz (skrzynka phishingu, terminal) nie trafiają na listę.
Sesja zawsze ma pytaniaBez błędów powtórka staje się treningiem mieszanym, więc da się ją ukończyć, a ranga „Strażnik sieci” jest osiągalna.
Bez wyzwania dniaPowtórka, słownik i egzamin są wykluczone z losowania wyzwania dnia w dailyGame().

dailyWyzwanie dnia. Gra dnia wynika z daty, więc jest taka sama przez cały dzień.
badgesZdobyte odznaki z datą.
difficultyWybrany poziom trudności, wspólny dla wszystkich gier.
mistakesBłędy do powtórki: klucz idGry:skrót i data złej odpowiedzi.

Ranga zależy od odsetka ukończonych gier (10, 25, 45, 70 i 100%), więc dodanie nowych gier nie psuje progów.

Wdrożenie

Aplikacja działa na każdym hostingu statycznym (GitHub Pages, Cloudflare Pages, Netlify). Przed publikacją uzupełnij pola [[...]] w polityka-prywatnosci.html, regulamin.html, robots.txt i sitemap.xml oraz ustaw na hostingu nagłówki bezpieczeństwa (CSP, HSTS, X-Content-Type-Options, Referrer-Policy).

Autoplayer

tests/e2e/helpers.js zawiera funkcję, która przechodzi grę bez znajomości odpowiedzi: klika odpowiedzi, przyciski „Dalej” i obsługuje nietypowe mechaniki w funkcji special() (terminal, uprawnienia, dopasowywanie, układanie, CTF). Opcja stopAfter zatrzymuje grę w trakcie, a resume kontynuuje, dzięki czemu testy sprawdzają też stany pośrednie.
